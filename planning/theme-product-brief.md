# IdeaPocket 主题整理简版产品规划

整理日期：2026-09-30。状态：用户已批准并实施首轮阶段 1–2，尚未发布；阶段 3 仍为后续规划，版本与发布日期待定。

**产品目标**

让笔记在持续积累中自动形成可理解、可找回、可继续思考的主题，减少反复手动整理，同时保护用户已经建立的分类意图。沿用个人、本地优先的产品边界；本规划聚焦文字笔记关系与主题整理。

主题定义：围绕同一对象、问题或目标，放在一起阅读、比较或推进更有价值的一组笔记。不同观点可以属于同一主题；一条笔记可以属于多个主题，弱关联内容允许暂不归类。

**核心产品规则**

| 维度 | 建议规则 |
|---|---|
| 关系判断 | 综合对象、问题、目标和上下文；共同关键词只作为线索。归属应有来源片段和简短理由。 |
| 主题粒度 | 默认围绕具体问题形成中等粒度主题。例：“语音记录”是概览，“转写质量 / 录音操作体验”是主题，“地铁噪声 / 松手误发送”可随内容增长成为子主题。 |
| 主题成立 | 检查共同内容是否清晰、证据是否独立、是否增加找回价值；数量门槛需通过样本校准。人工创建主题允许从一条笔记开始。 |
| 新增笔记 | 明确相关时自动加入；弱关联显示建议；新方向积累为候选。成熟主题的自动更新不移动未修改的旧笔记，也不改写用户命名与范围。 |
| 结构调整 | 候选主题可自动调整；成熟主题的改名、合并、拆分先展示影响范围，由用户采用或忽略，采用后可撤销。 |
| 人工约束 | 手动加入、移出、范围说明、命名与摘要编辑持久保存，优先于自动结果；用户可以撤销约束。 |
| 摘要更新 | 仅依据最终有效成员生成；成员或正文变化后标记待更新。自动摘要保存版本，人工摘要保持原稿并接收更新候选。 |

**建议的使用流程**

首次启用时说明分析范围与联网方式，提供自动整理开关、暂停和手动补跑入口。笔记保存先完成，分析在前台可用时批量处理，下次打开可继续；不承诺手机后台持续运行。

保存笔记 → 分析内容与检索相关候选 → 校验关系 → 加入已有主题或积累候选 → 批量更新摘要与变化记录。

主题页展示成熟主题、候选主题及本轮变化。详情展示主题范围、来源笔记和归属理由，提供改名、范围编辑、加回 / 移出笔记、撤销、自动加入开关。合并与拆分建议集中处理，避免每次记录都打断用户。

用户编辑或明确保留后，主题成为“用户管理的主题”。这不强制冻结成员：用户可选择自动加入或仅接收建议。隐藏、归档与内容版本分别管理；隐藏主题允许恢复。

**与当前产品的差异**

以下“当前实现”是实施前核对的工作区基线，用于保留改动对照；首轮完成后的功能事实见 `FEATURES.md`，不代表已发布包。

| 能力 | 当前实现 | 规划改动 | 阶段 |
|---|---|---|---|
| 分析触发 | 手动分析全部有效笔记；变化只提示重新分析 | 新增、编辑笔记触发局部分析，保留全库检查与手动补跑 | 2 |
| 关系解释 | 输出标题、摘要、成员及关键词 | 增加归属理由、支持片段和弱关联建议 | 2；跨主题关系在 3 |
| 粒度与数量 | 单层主题；每轮最多 5 个主题，生成主题至少 3 条成员 | 以问题明确度与找回价值确定粒度；将每轮 5 主题硬限制改为按预算分批发现，展示数量单独控制 | 2；层级在 3 |
| 多重归属 | 一条笔记最多进入 2 个本轮生成主题 | 保留多重归属，按关联质量抑制重复；人工归属不受自动生成数量限制 | 2 |
| 用户管理 | 已保留主题固定；只有历史主题有保留入口 | 当前主题也可保留；用户管理与自动加入开关分开设置 | 1–2 |
| 人工纠偏 | 可改名、移出；排除记录依赖旧新主题匹配，存在回流边界 | 独立保存加入 / 排除约束，增加加回与撤销；支持范围编辑与人工创建 | 1–2 |
| 历史 | 未匹配主题进入历史；匹配主题直接更新；来源读取当前正文 | 稳定主题身份与内容版本分开，记录成员 / 摘要变化及来源版本 | 1 |
| 摘要可信度 | 移出成员不更新摘要；本地摘录也显示“AI 核心总结” | 成员与摘要一致，支持待更新状态、版本及来源标识 | 1 |
| 结果状态 | 空结果保留旧主题并更新分析指纹；缺失字段可能被视为空结果 | 区分失败、有效空结果及未采用结果，注明旧结果有效性 | 1 |
| 解散与隐藏 | 解散后从列表消失，并抑制近似主题；没有恢复入口 | 拆分隐藏、恢复、归档和抑制此方向的意图 | 1–2 |
| 合并与拆分 | 拆分复核在生成流程内部执行，无可审阅的结构调整方案 | 对成熟主题提供可比较、可采用、可撤销的建议 | 3 |
| 长期规模 | 全量请求；大输入截取笔记开头；本地两两比较 | 缓存覆盖全文的内容表示，检索局部候选，按总预算批量处理 | 2 |
| 备份恢复 | 导出主题但遗漏部分纠偏字段；导入清空主题集合 | 完整恢复主题、人工约束、版本与设置；合并保留现有主题并映射笔记 ID | 1 |

继续保留：来源笔记可追溯、原文查看、多重归属、未归类内容、本地存储、分析异常提示和手动控制入口。

**实施顺序与交付范围**

| 阶段 | 交付重点 | 完成门槛 |
|---|---|---|
| 1：保护整理结果 | 纠偏持久化与撤销、当前主题保留、隐藏恢复、摘要一致性、历史版本、完整备份恢复与结果状态 | 同一笔记的明确排除不回流；旧结果可追溯；恢复后人工设置一致；空结果不把旧摘要标为最新 |
| 2：建立自动闭环 | 候选 / 自动 / 用户管理主题、增量归属、全文内容表示与候选检索、归属理由、范围编辑、人工创建、自动加入开关 | 保存不等待分析；新增笔记不重排成熟分类；编辑 / 删除只更新相关内容；人工约束优先；失败可继续处理 |
| 3：完善主题结构 | 上下层主题、合并 / 拆分建议、跨主题关联与范围筛选 | 结构变化能比较、撤销；桥接笔记不把独立主题强行合并；细分有实际找回价值 |

阶段 1 与阶段 2 构成建议的首轮产品范围；阶段 3 依据使用证据再推进。尚未设定发布日期或量化收益；首轮暂用 2 / 3 条不同内容作为候选 / 成熟门槛，并保留待样本校准的关联阈值。

**架构与存量迁移要求**

内容表示、关系检索、主题归属、命名摘要与更新规则分别处理。主题使用稳定 ID；人工约束独立保存，主题成熟度、管理方式、展示状态和内容版本分别建模。请求应有整轮预算、取消与恢复路径。

存量主题先保留名称与成员：“当前”映射为已有自动主题；“已保留”映射为用户管理且默认关闭自动加入；旧历史继续可访问；已解散记录保留现有抑制信息并提供恢复。首次迁移不自动重聚合，也不从现有数据补造过去的正文快照。旧记录缺少版本证据时明确标注。

**验证与文档边界**

固定验证：明确排除后重分析、手动加入后自动分析、修改成员后摘要更新、相反观点同题、桥接笔记跨题、长笔记尾部包含核心内容、空结果、请求中断、备份往返与旧数据迁移。用人工判断过的笔记集观察归属准确性、主题可理解性、找回时间、分类变动和纠偏回流；具体目标待建立基线后确定。

现状依据：`src/lib/themeAggregation.js`、`src/themeActions.js`、`src/useNotes.js`、`src/presentation.js`、`src/screens/ThemesScreen.js`、`src/screens/ThemeDetailScreen.js`、`src/lib/backupExport.js`、`src/lib/backupImport.js`、`FEATURES.md`。规划依据：本次会话对笔记关系、粒度、自动更新与人工控制的分析。
